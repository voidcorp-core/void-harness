# Agent audit: `silent-failure-hunter`

## Need

Without this agent, swallowed failures slip through every existing layer. The
PreToolUse hooks catch the grep-able floor but cannot tell a deliberate ignore from
a dropped error; `/code-review` finds wrong-but-loud bugs, not quiet ones; the
`async-safety` and `observability` skills define the discipline but nothing audits a
diff against it in an isolated context. The result: an `catch {}` turns a crash into
silent corruption, an un-awaited promise loses its rejection, an ignored `Result`
hides a failure branch. `silent-failure-hunter` is the read-only, narrow audit of
exactly that class of defect, and nothing else.

## Decision matrix anchor

- **Wins**: finding errors that are lost without a trace — empty/log-only catches,
  `.catch(()=>{})`, un-awaited promises, ignored return codes/Results, boundary
  swallowing that masks "broken" as "empty", over-broad catches.
- **Loses to**: `/code-review` for general correctness/perf (wrong-but-loud bugs);
  `/cso` for security; `doctrine-critic` for taste/anti-bloat/test-meaning.
- **Cannot decide**: whether a documented ignore is acceptable (advisory; surfaces
  it, the human/author decides). It does not gate.
- **Composes with**: `async-safety` (the un-awaited / at-least-once discipline),
  `observability` (an error that is never recorded is unobservable), `code-review`
  (inherits blocker/suspicious framing), `doctrine-critic` (sibling read-only critic,
  disjoint scope).

## Adaptation strategy

**original (compose-not-duplicate).** Authored for void-harness as a narrow,
read-only audit. It re-implements no general review and no security engine — it
audits one defect class the other layers miss, and routes the rest.

## Adaptations and rejections

- **Rejected general review scope.** Anything wrong-but-loud routes to
  `/code-review`; the agent stays under the 30% overlap ceiling (anti-bloat rule 3)
  by hunting only *silenced* failures.
- **No first-class write tools.** `tools: Read, Grep, Glob, Bash` — Edit/Write/
  NotebookEdit omitted; `Bash` is observation-only by prose convention.
- **`model: sonnet`.** Pattern-spotting against known anti-patterns is a recognition
  task, not deep design reasoning — Sonnet is the right tier for cost/latency.

## Anti-rules (what this agent MUST NOT do)

- MUST NOT review general correctness, logic, or performance → `/code-review`.
- MUST NOT audit security → flag the location, route to `/cso`.
- MUST NOT judge doctrine/anti-bloat/test-meaning → `doctrine-critic`.
- MUST NOT edit the tree (no Edit/Write; Bash read-only by convention).
