# Agent audit: `code-explorer`

## Need

Without this agent, understanding an unfamiliar codebase happens in the main thread:
the agent reads dozens of files, and its context window fills with raw detail it will
not reference again, crowding out the actual task. `code-explorer` absorbs that
exploration in an isolated context and returns only a compact structured map
(entrypoints, main flows, where things live, key deps). The pain it prevents is
context exhaustion and the loss of the working plan under a pile of file dumps. Its
entire value is the *compression* — explore widely, report tightly.

## Decision matrix anchor

- **Wins**: orienting in an unfamiliar codebase/slice and returning a dense,
  skimmable map without flooding the caller's context (the context-isolation pattern).
- **Loses to**: `doctrine-critic` (quality/doctrine judgement), `/code-review`
  (bugs/perf), `/cso` (security), `type-design-analyzer` (type design),
  `silent-failure-hunter` (swallowed errors) — it maps where these live; it does not
  perform any of them.
- **Cannot decide**: anything evaluative. It is descriptive only — no verdict, no
  grade, no fix.
- **Composes with**: `context` (it *is* the context-isolation tool in
  practice — a sub-agent that protects the main window), `doctrine-critic` and the
  other read-only critics (it hands them a map to act on).

## Adaptation strategy

**original (compose-not-duplicate).** Authored for void-harness as a pure
read-only cartographer. It judges nothing and fixes nothing; that disjointness from
every critic is what keeps overlap near zero.

## Adaptations and rejections

- **Rejected any evaluative scope.** The agent never grades, reviews, or refactors —
  "Notable" findings are stated as neutral facts and routed. This keeps it strictly
  complementary to the critics (anti-bloat rule 6).
- **Compact-by-contract.** The output format forbids pasting files; it quotes a
  signature or a path. The whole point is to *not* spend the caller's context.
- **No first-class write tools.** `tools: Read, Grep, Glob, Bash` — write tools
  omitted; `Bash` observation-only (`ls`, `find`, `grep`, `git log`) by convention.
- **`model: sonnet`.** Mapping structure is breadth/recognition work, not deep
  reasoning; Sonnet's speed and cost fit the "read a lot, summarise" profile.

## Anti-rules (what this agent MUST NOT do)

- MUST NOT judge quality/doctrine → `doctrine-critic`.
- MUST NOT find bugs/perf → `/code-review`; audit security → `/cso`.
- MUST NOT analyse type design (`type-design-analyzer`) or error handling
  (`silent-failure-hunter`) — only locate them.
- MUST NOT edit the tree, and MUST NOT pad the map with content it was not asked for.
