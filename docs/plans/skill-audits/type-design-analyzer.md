# Agent audit: `type-design-analyzer`

## Need

Without this agent, type *quality* is judged only mechanically. The `no-any` /
`no-as-cast` hooks ban unsafe escapes; `typescript-strict`, `functional`, and
`api-and-interface-design` describe what good types look like; but nothing audits a
diff for whether the type *design* is sound — whether a `status: string` should be a
union, whether four optional fields encode two states a discriminated union would
make exact, whether a DB row shape leaks straight into the domain. Those are taste
calls no hook can make and a generic reviewer does not center on.
`type-design-analyzer` is the read-only, context-isolated judge of exactly that, and
nothing else.

## Decision matrix anchor

- **Wins**: judging type design — make-illegal-states-unrepresentable, primitive
  obsession, missing discriminated unions / exhaustiveness, leaky boundary types,
  over-wide types, nullability honesty.
- **Loses to**: `/code-review` for runtime correctness/perf; `/cso` for security
  (input validation as a trust boundary); `doctrine-critic` for doctrine/anti-bloat.
- **Cannot decide**: whether to ship (advisory; does not gate). Whether an opaque
  `string` is genuinely opaque (proposes, author confirms).
- **Composes with**: `typescript-strict` (sits above the `no-any` floor), `functional`
  (discriminated unions, sum types), `api-and-interface-design` (boundary vs domain
  types), `code-review` (blocker/nit framing), `doctrine-critic` (sibling critic,
  disjoint scope).

## Adaptation strategy

**original (compose-not-duplicate).** Authored for void-harness. It re-implements no
type checker (that is `tsc`) and no general review — it judges the *design* taste
layer above the strict-mode floor, and routes the rest.

## Adaptations and rejections

- **Rejected general TS review.** Runtime bugs in well-typed code route to
  `/code-review`; the agent only judges shape, keeping overlap under 30%
  (anti-bloat rule 3).
- **No first-class write tools.** `tools: Read, Grep, Glob, Bash` — write tools
  omitted; `Bash` observation-only (`tsc --noEmit`, `git diff`) by convention.
- **`model: opus`.** Judging whether a type admits an illegal state, and proposing
  the sounder sum type, is deep design reasoning — the top tier is justified here
  (contrast `silent-failure-hunter`, a recognition task on Sonnet).

## Anti-rules (what this agent MUST NOT do)

- MUST NOT review runtime correctness/perf → `/code-review`.
- MUST NOT audit security/input-validation trust boundaries → `/cso`.
- MUST NOT judge doctrine/anti-bloat/test-meaning → `doctrine-critic`.
- MUST NOT edit or implement the new types (no Edit/Write; proposes only).
