# Allowlist only certified generated enforcement artifacts

## Context

The CI enforcement runner rejects inputs above 1 MiB by design. The generated
`packages/core/graph/void-graph.mjs` consumer bundle is a deterministic,
single-line artifact above that bound, so scanning its added text fails closed
before any rule can run. Its authored TypeScript, embedded model and Studio
sources are already scanned, while `pnpm graph:check-bundle` proves that the
committed bundle matches those inputs.

## Decision

We will exempt only the exact generated graph bundle from `void-enforce`, keep
the skip visible in logs, and require its authored sources plus deterministic
freshness gate to remain active in the same CI.

## Consequences

Positive:

- The 1 MiB fail-safe bound remains strict for ordinary files.
- Authored source stays under secret, TDD and dependency-boundary checks.
- The published single-file bundle keeps its account-free consumer contract.

Negative:

- The generated bytes are not scanned directly by the enforcement runner.
- Correctness depends on `graph:check-bundle` remaining a required CI gate.

## Alternatives considered

- **Raise the global input limit**: rejected because every untrusted edit would
  receive the larger memory and processing budget.
- **Chunk the minified line in the shell driver**: rejected because rule matches
  can cross arbitrary byte boundaries and a partial scan could create a false
  green.
- **Split the consumer artifact**: rejected because the current distribution
  contract intentionally ships one self-contained, account-free file.

## Reversal cost

Low. Remove the exact allowlist entry after a bounded streaming protocol or a
certified multi-file consumer format replaces the current bundle.
