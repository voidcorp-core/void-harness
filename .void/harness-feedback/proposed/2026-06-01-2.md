# Trigger

Working on core logic inside `packages/**` this session, `tdd-guard` never
blocked a production edit that had no sibling test. Reading the hook
(`tdd-guard.sh:28`) shows why: `BUSINESS_GLOB="apps/*/src/**"` is the default,
and the business-path check at `:60` exits 0 for anything outside it. The harness
repo itself does not set `.paths.business` to include `packages/`, so its own
densest logic runs unguarded.

# Observation

The strictest discipline (a test file must exist before production code) is
enforced exactly where the thinnest app glue lives (`apps/*/src`) and skipped
exactly where the load-bearing library code lives (`packages/*/src`). This is a
silent coverage hole: the absence of a block reads as "TDD floor satisfied" when
in fact the path was never checked. The glob is configurable, but the *default*
is single-app-shaped and wrong for any repo with a library layer — monorepos,
published packages, and void-harness itself.

This is the same root cause as the existing friction note
`plans/frictions/2026-06-01-paths-single-app-shape.md`: `DEFAULT_CONFIG.paths`
assumes one app shape. That note argues for per-app/per-package path resolution;
this finding is the narrower, immediately-actionable slice (packages get no
coverage at all under the default).

# Proposed change

Broaden the default business glob to also cover library packages, e.g.
`packages/*/src/**` in addition to `apps/*/src/**` (a brace/alternation or a
second `case` arm). Alternatively ship a `library` / `monorepo` paths preset that
`init` selects when it detects a `packages/` workspace. Whichever lands, set
void-harness's own `.void/config.json` so the harness's core logic is guarded by
the rule it ships. Converge with the per-app/per-package resolution decision in
the friction note rather than solving paths twice.

# Rationale

A TDD gate is only worth its friction if it fires where logic is densest.
Defaulting it away from `packages/` means the harness preaches the Iron Law while
exempting the code most likely to need it — and does so invisibly, which is worse
than not having the gate at all.
